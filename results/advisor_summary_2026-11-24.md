# 自我測試與 S7 系統：進度摘要（2026-11-24，與老師討論用）

完整紀錄：`report.md` 35.76–35.83（每個數字都可以用 repo 裡的腳本重跑）。
受試者只有我本人（n = 1），只用來決定方向，不能當成研究結論。

## 1. 第一個實驗做完了：9 個方向手勢的自我測試

**做了什麼**：
- 4 顆 Trigno Avanti 貼在 EDC、FDS、FCR、FCU，複製成 8 通道；STM32H753 跑 LDA。
- 校正：9 個手勢各 2 輪、每次 4 秒。
- 3 段提示探測，加上 2 段任務（各 40 次手臂指令）。
- 錄了 2 次配戴：同一天，拆掉後對著畫的框重貼。

**錄之前定好的判準**，結果如下：

| 判準 | 結果 | 判定 |
|---|---|---|
| 1 手勢集（視窗準確率 ≥ 85 %，選最大的組合） | S9 70.9 %、**S7 82.6 %**、S5 80.3 % | 沒有組合過 85 % → 用最準的 **S7**，並修改判定方式 |
| 2 任務軟標籤（D̄ ≥ +2 點） | +2.31，兩次都為正；自我訓練對照兩次都為負 | **GO** |
| 3 跨配戴累積（D3 ≥ +2 點） | +1.73 | NO-GO（只有一次後續配戴，而且同一天） |

- Point（前）和 ThumbUp（後）的訊號接近放鬆，連放鬆都被拖下水（Rest recall 18–21 %），所以拿掉，改成 S7。
- 85 % 是我錄之前設定的工程門檻，沒有文獻依據。讀了 Nawfel 等（2021, IEEE TNSRE）：離線準確率不能代表好不好用，這篇也沒有給可用門檻。

## 2. 主要問題：放鬆時手臂會自己動，已經解決

- 原本的判定方式（連續 3 個一致），放鬆時每分鐘誤觸發約 40 次，大約每 1.5 秒手臂就會自己動一次。
- 原因有兩個：
  - 校正姿勢（前臂平放）和使用姿勢（手臂伸出）不同，撐著手臂的放鬆被判成手勢；
  - 第 1 次校正的放鬆段含有 60 Hz 雜訊。
- 解法：
  - **活動量門檻**：強度低於「這次校正手勢中位數」的 0.5 倍，就直接當成放鬆；
  - 開始動要 **5 個**一致，停下只要 **2 個**一致。
- 用一次配戴挑參數、另一次驗證：休息時誤觸發降到每分鐘 0.4–1.1 次，指令正確率約 89–93 %，延遲約 1.2–1.4 s。

## 3. 已經放上板子，並在實機驗證

- 韌體（`rtl_task_s7e`，已燒錄）：S7 類別遮罩、活動量門檻、停止事件，以及**事後標籤的範圍標籤**（保留最近 256 個視窗）。
- 每一步都照同一套驗證流程：
  1. PC 版和 Python 逐視窗相同；
  2. 既有的回歸測試不變；
  3. 燒錄前後讀回比對，模型區沒有變動；
  4. **同一份資料送進板子和 PC，輸出逐筆相同**（1,511 個視窗、全部指令）。
- 實機測試抓到一個 PC 測試沒發現的 bug：兩個範圍標籤同時到時，第二個會被丟掉。改成佇列後，實機確認兩個都有套用。
- PC 工具：控制面板預設 S7，錄音檔名 `_S`；提示畫面、橋接程式、分析程式都更新了；SOP 也更新了。

## 4. 往機械臂的路已經接通（模擬）

- **全系統彩排**：錄好的 EMG → **真的板子** → 橋接程式 → Gazebo 裡的 Gen3 手臂。
  - 板子的 41 個指令／停止事件全部依序送到手臂；
  - 停止之後手臂沒有任何一步還在動；3 個物體都沒被碰到。
- **閉迴路模擬**：全程用真的韌體程式碼，播放我自己錄到的 EMG，模擬使用者做取放任務，事後標籤送回韌體。
  - 標籤本身的錯誤只有 0.3–1.1 %；
  - 模型本來表現差的時候，標籤幫助很大（模型沒看過的片段，往錯方向動 19.6 % → 6.9 %）；
  - 本來就好的時候沒有幫助，甚至讓鎖錯目標變多。原因還在查，可能要加遺忘。
