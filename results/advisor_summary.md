# 前置研究結果摘要（與教授討論研究方向用）

論文題目：在 STM32H7 上實現有記憶體預算、不需要標籤的自我校正隨機森林（RF）肌電手勢控制
參考論文：Jiang, Ma, Nazarpour — J. Neural Eng. 2025（plug-and-play）、Front. Neurorobot. 2024（posture-invariant）
目標硬體：NUCLEO-H743ZI2（Cortex-M7，2 MB Flash，最大的連續 SRAM 是 AXI 512 KB）
完整報告：`report.md`（所有數字都可以用 repo 裡的腳本重跑）

## 1. 已完成的事（都有實際執行結果）

**(a) 成功重現 PC 基準**（作者公開的 arm_position 資料：20 人、11 個 block、5 種手臂姿勢）
- 自我校正 RF：**84.63 ± 8.58%**（論文 84.6 ± 8.5%）；固定的 one-shot 模型是 80.21%。20 人中有 18 人在自我校正後變好。
- 所有和論文對得上的數字（LDA、RF、各姿勢的增益）差距都 < 1 個百分點。
- 讀程式碼時發現程式和論文描述不一致的 4 個地方：
  - 剪枝條件：論文寫 `≤`，程式是 `>`。
  - 偽標籤初始化：論文寫用當下的模型，程式其實一直用最初的 one-shot 模型。
  - 比較方向：預測用 `<`，剪枝用 `<=`。
  - bootstrap 比例：論文寫 7%，實際模型是 1%–2%。
  - 另外，偽標籤**沒有使用任何信心門檻**。

**(b) 模型可以壓縮，而且自我校正後的準確率幾乎不受影響**

| 設定（樹數、深度、精度） | Flash（實際編譯） | one-shot | **自我校正後** | 和完整模型的差距 |
|---|---|---|---|---|
| 400 棵、深度不限、float32（論文原樣） | 693.8 KB | 80.03% | **84.46%** | — |
| 400 棵、深度 10、int16 | 345.5 KB | 79.84% | 84.37% | −0.06 |
| **100 棵、深度 10、int16（推薦）** | **88.1 KB** | 79.68% | **83.96%** | **−0.47** |
| 50 棵、深度 8、int16 | 約 23 KB（估算） | 78.77% | 83.19% | −1.24 |
| 20 棵、深度 10、int16 | 約 17 KB（估算） | 77.17% | 81.93% | −2.50 |

（自我校正：3 個 seed × 20 人；完整模型用 float64 是 84.43%。50 棵和 20 棵沒有實際編譯，Flash 是用格式算出來的大小。）
- int16 定點量化在所有設定下都**沒有準確率損失**（≤ 0.02 個百分點）；深度 10 和不限深度幾乎一樣。
- 不論模型大小，自我校正的增益都是 +4.3 到 +4.8 個百分點。

**(c) 推論可以在 Cortex-M7 上執行**（arm-none-eabi-gcc 10.3，-Os）
- 推論 RAM 實測只要 **552 B**（特徵緩衝區 + 最壞情況的 stack）。
- C 版和 Python 版在 3300 筆測試資料上的預測 100% 一致。
- 自寫的 RF 格式比 emlearn 小 12.5%–65%，而且沒有 emlearn 用 `%.6f` 印門檻值的精度問題。
- 還沒做的：在板子上量 cycle 數；模擬器不模擬 M7 的 cycle，所以沒有報這個數字。

## 2. 關鍵發現：瓶頸在「自我校正」的記憶體，不在推論

在 MCU 上做自我校正需要的 RAM（**依設計計算的估算**；可替換的附加樹大小是實測值）：

| 情境 | RAM 合計 | 放得進 AXI 512 KB？ |
|---|---|---|
| A 照論文原樣：float32 buffer（1500 筆）、400 棵、t-SNE + K-Means | **約 1208 KB** | 否（連全部 SRAM 都不夠） |
| B int16 buffer、100 棵、t-SNE + K-Means | 約 735 KB | 否 |
| C int16 buffer、100 棵、**只用 K-Means（不做 t-SNE）** | **約 334 KB** | 是 |

主要的記憶體開銷：
- t-SNE（Barnes-Hut）：約 401 KB
- buffer：float32 469 KB／int16 234 KB
- 自我校正後的附加樹：50 棵最大 38.8 KB；論文設定的 200 棵最大 267.8 KB，因為樹會從每棵 13 個節點長到平均 105–149 個（依深度而定）

**問題是**：論文的 ablation 顯示，拿掉 t-SNE、只做 K-Means 時準確率是 81.0%，完整方法是 84.6%，掉了 3.6 個百分點。
也就是說，**唯一放得進 MCU 的做法（情境 C）剛好是論文裡準確率最差的版本**。

## 3. 建議收斂的研究問題

> **在固定的 RAM 預算下（例如 ≤ 256 KB 或 ≤ 512 KB），怎樣的無標籤偽標籤方法和 buffer 設計，能夠保住 t-SNE 版本的自我校正增益？**

可能的貢獻方向（這些都還沒做，是提案）：
1. **低記憶體的偽標籤方法**：取代 t-SNE + K-Means。候選：
   - 用 calibration 資料訓練的 LDA 投影到 5 維再做 K-Means（投影矩陣只有約 1.6 KB）
   - PCA + K-Means
   - 用 RF 的投票信心做門檻篩選
   - 小 buffer 版 t-SNE（例如 500 筆）
   
   目標是準確率接近 84.4%，RAM ≤ 50 KB。
2. **buffer 壓縮**：buffer 改存 int16（推論已確認沒損失），並縮小 buffer，畫出「buffer 大小 vs 自我校正增益」的曲線。
3. **有界的樹更新**：限制新樹的大小（例如 `max_leaf_nodes`），讓附加樹佔用的 RAM 有固定上限，並量準確率代價。
4. **系統實作**：特徵擷取（濾波 + FFT，約 18 KB）+ 推論 + MCU 上的 RF 訓練，在 H743 上完整跑一次，量時間和功耗。

## 4. 想和教授討論的問題
1. 研究重點要放在「演算法：低記憶體偽標籤」，還是「系統：完整移植到 MCU」？兩者都做的話，時程怎麼排？
2. RAM 預算要訂多少？只用 AXI 512 KB，還是要求 ≤ 256 KB，讓它也能移植到 H7 以外的 MCU？
3. 評估是否只用作者公開的資料（20 人 arm_position、1 人 demo）就夠？是否需要自己收資料、做線上實驗？
4. 自我校正（RF 重新訓練）要在 MCU 上做，還是可以接受「MCU 收資料、手機或 PC 重新訓練、再下載模型」的折衷做法？
