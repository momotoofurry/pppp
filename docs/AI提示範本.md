# 給 AI 的提示範本（Claude、GPT、Gemini）

複製後把〔〕裡的換掉。所有範本都假設 AI 能讀到這個 repo：在 `~/model-leaf` 啟動的 Claude Code／Codex／Gemini CLI，或給它 GitHub 網址的網頁版。

## 寫提示的原則
1. **一次一件事**，說清楚「要做什麼、做到什麼程度算完成」。
2. **要它先查證**：建議和數字都要附上出處（檔案:行號、report 節次），沒查到的要說沒查到。
3. **限制寫明**：不改凍結的東西、不自己填論文數字、push 前先問。
4. **要它先給計畫再動手**，大的改動尤其如此。

## 1. 開始一個新的工作階段（每次換 AI 或換帳號的第一句）

```
請先讀 AGENTS.md，再讀 claude/memory/MEMORY.md 和它列出的每個檔案，最後讀 docs/接續工作指南.md 第 3 節。
讀完後用繁體中文告訴我：(1) 你理解的研究目標；(2) 目前做到哪裡；(3) 下一步有哪些。先不要改任何檔案。
```

**網頁版的 ChatGPT／Gemini**（不能直接讀本機檔案）：
```
這是我的碩論專案：https://github.com/momotoofurry/pppp
請先讀 AGENTS.md、claude/memory/MEMORY.md、docs/接續工作指南.md。之後的回答都要根據 repo 的內容，引用時附上檔案路徑或 report 節次；repo 裡查不到的，請明說是推測。
```
讀不到網址時，就上傳這三個檔案，加上和問題有關的檔案。

## 2. S7 錄完之後的分析

```
我錄完了 S7 的兩天：〔T00_d1_S〕和〔T00_d2_S〕，在 D:\selftest_data\T00\。
請照 docs/接續工作指南.md 第 3 節的順序跑：
(1) 凍結判定（selftest_quality、selftest_s7_prereg、selftest9_analysis --sets S7）；
(2) R16 取對數的確認；
(3) R19 60 Hz 閘門（不加 --dev）。
判準都已經寫死，只照判準報結果，不要調參數。每一項給我：數字、通過或不通過、結果檔的路徑。
最後把結果寫成 report 的新一節並 commit，但先不要 push。
```

## 3. 請另一家 AI 做審查（第二意見）

```
請審查〔src/c/rt_lda.c 的 range_update〕〔或：report 35.103〕。
要求：
- 每個問題都要指出檔案:行號，並說明在什麼輸入或時序下會出錯；
- 先確認 repo 裡是否已經處理過（AGENTS.md、report、測試），已處理的請標明「已處理，見 …」；
- 分成「真的錯誤」「可以改進」「只是風格」三類；
- 不要改檔案，只要報告。
```

拿到外部的建議（例如另一家 AI 的評論）時：
```
以下是別人對這個專案的建議。請逐條對照 repo 查證：已經做了的（附出處）、部分做了的、真的沒做的、前提不成立的。
真的沒做而且值得做的，排出優先順序並估工作量。先不要動手。
〔貼上建議〕
```

## 4. 動手改程式

```
目標：〔例如：把 35.103 的雙緩衝和 35.104 的 seqlock 做成下一版韌體〕。
完成的條件：〔例如：PC 的 check_* 全部逐位元相同；firmware/build_fw.sh 編得過；寫出 RAM／Flash 用量〕。
限制：板子上的 rtl_task_s7f 不燒；凍結的判準不改；CRLF 的檔案保留換行；每個階段 commit，不要 push。
請先給我計畫（要改哪些檔案、怎麼驗證），我同意後再做。
```

## 5. 寫論文

```
請幫我寫〔第 3 章方法的 3.x 節：…〕。
規則（claude/memory/thesis-writing-rules.md）：只引用 docs/ 裡已有的文獻，格式（作者，年份）；缺文獻寫【此處需補文獻】；
自我測試的數字寫【待填】；模擬數字只能用 report 裡有的，並標〔35.xx〕。
內容依據 report 的〔35.xx–35.yy〕。先給大綱，我確認後再寫全文。
```

## 6. Kinova 實機當天

```
今天要做 Kinova 實機，照 lab_kit/SOP_Kinova實機.md。
請先陪我做第 1 節的上機前檢查（loop_jitter 300、單元測試、假硬體測試），每一項告訴我通過條件和實際結果。
實驗中請用 tools/local-monitor 即時監看 ~/kinova_k〔1〕，有 high 等級的警示就立刻告訴我。
你只能讀紀錄、不能送指令給手臂；安全由協助者和急停負責。
```

## 7. 結束一個工作階段

```
請整理這次做了什麼：改了哪些檔案、commit 的雜湊、還沒做完的事、需要我決定的事。
把新的決定或進度寫進 claude/memory/（照現有格式，並更新 MEMORY.md 的索引），然後 commit。
```
