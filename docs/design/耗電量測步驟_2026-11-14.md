# 耗電量測步驟（2026-11-14，三用電表）

目的：量出 STM32H753（480 MHz）在幾種固定負載下的平均電流，再換算成「每次 LDA 更新」與「每個視窗」的耗能，以及即時運作時的平均功率。

量測韌體已寫好並在板上試跑過一輪，所有狀態都正常。試跑完已還原成凍結版韌體。韌體在 `D:\stm32\blink_leaf\build\energy\blink.elf`，原始碼在 `emg_energy_src\energy_bench.c`。

## 需要的東西
- NUCLEO-H753ZI 和 USB 線（電腦或 USB 充電器都可以供電）。
- 三用電表：有直流 mA 檔，表筆接 **COM** 和 **mA** 孔。
- 紙筆或手機，記下 7 個讀數。

## 步驟
1. **我先把量測韌體燒進去**：板子接電腦，跟我說一聲，我燒錄。燒完會在序列埠看到 `=== energy states ===`。
2. **拔掉 USB，讓板子完全斷電。**
3. 找到板上絲印標 **IDD** 的跳線帽（兩根針加一個帽），把帽子拔掉收好。
4. 三用電表切到**直流電流 mA 檔**。先選**最大**的 mA 檔；如果只有 10 A 檔可以撐住，就先用 10 A 檔。紅棒、黑棒分別夾在 IDD 的兩根針上。
   - 方向接反只會顯示負號，不會壞。
5. 插回 USB。板子會自己開始跑，不需要電腦傳資料。
   - 斷電再上電，也會關掉燒錄時留下的除錯電路，讀數才準。
6. 板子會依序跑 7 個狀態，每個 30 秒，跑完一輪再從頭開始，一輪約 3.7 分鐘。
   - **綠燈 LD1 閃幾下，就是第幾個狀態**。閃完之後的 30 秒燈都是暗的，這段時間才是量測時間。
   - 閃完後等 **5–10 秒**讓讀數穩定，再記下數字。
7. 記滿一輪後，再記第二輪，看兩輪差多少。
8. 量完：**先拔 USB 斷電，拆下電表，把 IDD 跳線帽插回去**，再接回電腦給我還原韌體。
   - 千萬不要在通電時拔跳線帽或換檔：電路一斷，MCU 就會重開機。

**檔位注意**：
- 讀數穩定之後，可以試著換到更小的 mA 檔，精度會比較好；換檔前一樣要先斷電。
- 換到小檔後，如果板子一直重開機（綠燈從頭閃），或讀數亂跳，表示電表在小檔的壓降太大。就退回大檔，並在表上註明用的是哪一檔。

## 7 個狀態與記錄表

| 閃幾下 | 狀態 | 板子在做什麼 | 第一輪 mA | 第二輪 mA |
|---|---|---|---|---|
| 1 | spin | CPU 空轉，醒著但什麼都不做 | | |
| 2 | wfi | 睡眠（WFI），每 1 ms 被時脈叫醒一下 | | |
| 3 | fit | 不停做 LDA 求解（每次 3.87 ms） | | |
| 4 | update | 不停做一次任務軟標籤更新（每次 4.66 ms） | | |
| 5 | window | 不停處理 100 ms 的訊號視窗：濾波＋特徵＋分類（每個 2.73 ms） | | |
| 6 | realtime | 真實運作：2 kHz × 8 通道，每 100 ms 分類一次，其餘時間睡眠 | | |
| 7 | rt+upd | 同 6，再加每 2 秒一次任務標籤更新 | | |

另外記下：電表型號、用的是哪一檔、室溫大約幾度。

## 量完我會算的東西（3.3 V）
- **每次更新的耗能**（比睡眠多出來的）≈（狀態 4 − 狀態 2）mA × 3.3 V × 4.66 ms，單位是 µJ。
- **每個視窗的耗能** ≈（狀態 5 − 狀態 2）mA × 3.3 V × 2.73 ms。
- **即時運作的平均功率** ＝ 狀態 6 的 mA × 3.3 V，單位是 mW。
- **更新帶來的額外功率** ＝（狀態 7 − 狀態 6）mA × 3.3 V。
- 狀態 1 和狀態 2 的差：說明「沒事做時去睡」能省多少。

試跑時板子量到的時間（試跑紀錄在 `D:\stm32\blink_leaf\backup\energy_dryrun.txt`）：
- 即時運作時，處理訊號只佔 CPU 約 2.7%：每 100 ms 花 2.73 ms。
- 每 2 秒一次更新再多約 0.23%。

所以狀態 6、7 很可能只比狀態 2 多一點點，甚至在三用電表上看不出差別。**這本身就是結果**：即時運作的耗電幾乎就是睡眠耗電。表上照實記下就好。
