## 2. 第一週建議

1. 讀 `README.md`、`ARCHITECTURE.md`，再讀 report 的這幾節，理解為什麼走到現在的設計：
   - 35.3、35.9、35.16：為什麼放棄免標籤自我校正、改用短時有標籤校正＋LDA；
   - 35.38：為什麼不用神經網路；
   - 35.63：兩種模式的控制；
   - 35.76、35.86：自我測試的結果和凍結的判準；
   - 35.97–35.101：最近的研究和實驗設計。
2. 照 `README.md` 的「快速開始」跑單元測試。
3. 讀 `src/assist/modes.py` 開頭的說明，再用鍵盤在 RViz 操作模擬的手臂（`src/pc/sim/gen3_sim.sh`，再 `python3 src/pc/sim/assist_ros.py keys`），把兩種模式玩熟。
4. 自己照 `lab_kit/SOP_自我測試.md` 戴感測器、錄一次（流程熟了，才看得懂資料）。

## 3. 環境

| 用途 | 環境 |
|---|---|
| 分析、模擬 | WSL2 Ubuntu 22.04＋Docker；`docker/run.sh build` 建 `rf-emg` 映像（Python 3.12.3、固定套件、gcc、arm-none-eabi-gcc） |
| 手臂 | 同一個 WSL：ROS 2 Humble、`ros2_kortex`、Gazebo Classic。`src/pc/sim/gen3_sim.sh`（假硬體）、`gen3_gazebo.sh`（Gazebo）【待補：從零安裝 ROS 2 與 ros2_kortex 的步驟】 |
| 韌體 | Windows＋STM32Cube 的工具（gnu-tools-for-stm32 14.3.1、cmake、ninja、STM32_Programmer_CLI 2.23.0），見 `firmware/README.md` |
| 實驗室電腦 | Windows：Trigno Control Utility、`TrignoBridge.exe`、`TaskScreen.exe`、`ExperimentPanel.exe`（用 Windows 內建的 csc 編，不用安裝；見 `lab_kit/README.md`） |

**注意**：
- 在 WSL 裡跑的資料要放在 Linux 的檔案系統（`~/`），不要放 `/mnt/c`，很慢。
- 從 PowerShell 呼叫 WSL 時，不要把 bash 指令塞在 PowerShell 字串裡（`$` 會被展開），寫成 .sh 檔再執行。
- `src/assist/modes.py`、`src/pc/ExperimentPanel.cs`、`src/pc/sim/make_world.py` 是 CRLF 換行，用腳本修改時要保留原本的換行。

## 4. 可以接著研究的題目（依優先順序）

1. **Kinova 實機閉迴路**（RQ4，論文必做）：設計和工具都好了，剩下要決定的在 `lab_kit/實驗設計_Kinova實機.md` 第 10 節（協助者、韌體版本、判準的數字、夾取方式、物體間距）。
2. **確認取對數，做下一版韌體**（35.97）：在新的錄音上用 `src/structure_r16.py` 確認；確認後改 `features.c`（RMS、WL、MAV 取 log），重跑 C 和 PC 的比對與閉迴路模擬。
3. **真正的對照組：手動切換模式**（握拳切換模式、沒有自動鎖定和對準）：要證明輔助系統有價值，就要和一般輔助手臂的操作方式比。先寫程式和模擬使用者，估效果和需要的試驗數（35.99–35.100 的方法）。
4. **多位受試者**：要先通過 IRB、經指導教授同意。
5. **讓 MCU 不靠 PC**：Trigno 的類比輸出接 STM32 ADC（早期的「路線 A」），這樣「在 MCU 上」的主張才完整。
6. **擁擠場景的夾爪間距**：量 2F-85 手指後決定物體間距（35.101：中心距 8 cm 時，隔壁物體被推動約 1.9 cm）。
7. **語音／LLM 目標先驗**：模擬顯示辨識正確率要 ≥ 80 % 才值得接（35.86–35.87），目前列為未來工作。
8. **監控系統接即時資料**（`tools/emg-iot/`）：寫一個 UDP → MQTT 的轉接，在錄音時就提醒 60 Hz 干擾。

## 5. 試過、沒有用的（要重做，先有新的理由）

| 做法 | 結果 | report |
|---|---|---|
| 免標籤自我校正（原論文的方法） | 在獨立的重新配戴資料上沒有確認的增益 | 24、35.3、35.16 |
| 小型 MLP 取代 LDA | 每次配戴只有一輪提示時，可在 MCU 上更新的版本都沒贏 | 35.38–35.39 |
| 用 EMG 解碼的信心調整輔助（速度、推論、提早換指令） | 信心有資訊（AUC 0.83），但模擬裡都沒有幫助 | 35.94–35.95 |
| 扣掉底噪再取對數 | 結構上就被否定（方向沒變一致、偏度變大） | 35.98 |
| 依有效樣本數加大收縮 | 自我測試 −2.0、DB6 −0.02 點 | 35.98 |
| 在實機上比較模式 1 的導引輔助 | 效果只有約 1 s，實機做得到的試驗數下偵測不到 | 35.99–35.100 |
| 濾掉 60 Hz（陷波） | 準確率沒有提升（但對錄音品質有意義） | 35.97 |

## 6. 已知問題和坑

- **WSL 的暫停**：曾看到控制迴圈停 0.7–3.4 s，原因沒有確定；`assist_ros.py` 改用 monotonic 時鐘。實機前一定要照 `SOP_Kinova實機.md` 1.1、1.5 做（電源設定、300 s 時間檢查）（35.92–35.93）。
- **60 Hz 市電干擾是間歇的**，常在「放鬆」時出現；校正放鬆時被干擾，模型會把干擾學成放鬆。手臂離電源線和充電中的筆電遠一點（35.97）。
- **4 顆感測器時 ch5–8 是複本**：80 個特徵裡有 40 個重複（35.97）。
- **軟體的「放下」不算證據**：實機試驗一定要協助者確認物體真的站在目標架子上（35.101）。
- **每個試驗前要把物體歸位**：軟體會把物體位置重設成起點（35.101）。
- `src/assist/carry_test.py` 在舊版本就失敗，還沒修。
- report 第 1–34 節是隨機森林路線，很多設定（`pilot-freeze-5`、`PROTOCOL.md`）已經不用了，對照時注意節次和日期。

## 7. 安全和倫理

- 實機一定要有人在急停旁邊（`SOP_Kinova實機.md` 第 0 節）。
- 作者本人以外的受試者，要先有 IRB 和指導教授同意。
- 個人錄音不要放進公開 repo。
